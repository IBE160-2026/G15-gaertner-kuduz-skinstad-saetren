- (version) Web-verifisert 2026-09-29: FastAPI 0.141.1 (siste), React 19.3.0, Vite 8.3.1, TypeScript 5.9+ anbefalt for React+Vite-oppstart.
- (decision) Arbeidsmate: Coaching path. Leveranse: spinen (build-substrate) pluss noe forklarende materiale (presentasjon/enklere dokument) til gruppa/refleksjonsrapport, avgjort ved Finalize.
- (decision) Strukturell separasjon bekreftet: KI-modulen kan IKKE importere/kalle regelmotoren direkte. Den mottar kun et ferdig, validert, typet datasett (allerede filtrert og rangert av regelmotoren) som input og kan ikke endre det. Dette er den mest kritiske invarianten i spinen - handhever PRD S4.5s krav (KI beregner aldri harde regler/arbeidstid/kostnad, kan aldri overstyre Rangeringen).
- (decision) Stack (bruker delegerte valget, gruppen kan justere via GitHub senere): Backend FastAPI (Python), Frontend React + Vite. Valgt fremfor Django (unodvendig tungt, ingen admin/brukerportal-behov), Flask (mangler innebygd typevalidering som er nyttig for KI-grensen), Next.js (unodvendig for 4 linaere skjermer uten SEO-behov). Se version-loggen for verifiserte versjoner.
- (decision) Paradigme: Hexagonal (Ports & Adapters), lett utgave. Regelmotor = domenekjerne (ren Python, ingen avhengighet til KI-kode). Ett eksplisitt typet grensesnitt (Pydantic-modell, f.eks RangertKandidat) er eneste kontaktflate KI-modulen far se - 'porten'. FastAPI-endepunkter og React-frontend er driving adapters. Valgt over enklere lagdelt arkitektur fordi eksplisitt typet grense gir sterkere garanti enn en uskrevet importregel, for samme kompleksitetskostnad. Bekreftet av bruker - teamet kan endre senere via logg/update-modus.
- (decision) KI-leverandor: Google Gemini API (ekte gratis-tier, ingen kort, 1500 req/dag/15 req/min per web-sok 2026-09-29 - vs Claude API engangskreditt, OpenAI betalt). Kjoremiljo: kun lokal kjoring for na (ingen hosting besluttet) - kan legges til senere, f.eks. Render sin gratis-tier (750t/mnd, men 'sovner' etter 15 min inaktivitet).
- (decision) Datalagring: SQLite via SQLAlchemy (trengs for a huske godkjente erstatninger og innloggingssesjon mellom omstarter). Innlogging: brukernavn/passord i databasen (hashet passord), JWT-token for a holde okten innlogget. Testing: pytest pa backend, ett testmodul per hard regel (kompetanse-minstekrav, kolliderende vakt, 11-timersregel, 35-timersregel) - konvensjon, ikke bare praksis, jf. addendums vekt pa dette som kvalitetssikringsbevis. Alt bekreftet av bruker.
- (version) Web-verifisert 2026-09-29 (oppfolging): TypeScript 7.0.2 er na gjeldende (native Go-omskriving, TS 6.0 var siste JS-baserte). Forrige 'TypeScript 5.9+' var foreldet - rettet i Stack-tabellen. Gemini gratis-tier er modellavhengig og delvis strengere na (nyere Flash-modeller ca 20 gratis forespørsler/dag, Pro bak betaling siden april 2026) - mykere sprak i spinen, faktisk grense avhenger av hvilken modell gruppen velger.
- (change) Reviewer gate (rubrikk + web-verifisering + adversarial) kjort. Egne fikser anvendt uten a sporre bruker (mekaniske presiseringer, ingen nye produktbeslutninger): AD-1 styrket med runtime-invariant (ikke bare import-linter) og eksplisitt feltliste for RangertKandidat-porten inkl. utelukkelsesoppsummering; AD-2 utvidet handhevelse til alle adaptere; AD-3 klargjort hashing-eierskap (kun adaptere/lagring) og JWT-lagring (httpOnly cookie, ikke localStorage); AD-4 fikk minimal statusdiskriminator-form na istedenfor helt deferred; AD-5 fikk eksplisitt encaptulert skrivevei for Godkjenning-mutasjon; ny konvensjonsrad for tidssone (Europe/Oslo, DST-bevisst) pga SM-1/SM-5 reproduserbarhet; TypeScript oppdatert 5.9+ -> 7.0.2; Gemini-gratis-tier-pastand mykt sprak (modellavhengig); ERD-notat presisert at Avveining ikke er en varig lagret entitet (regenereres, kun Godkjenning persisteres).

Gjenstaende funn fra gjennomgangen er bevisst lagt i Deferred (Gemini-modellvalg/retry-policy, JWT-utlopstid, migreringsverktoy, Avveining-lasing ved Godkjenning, progressiv-lasting-transport) - ingen av dem er blokkerende for a starte implementasjon.
